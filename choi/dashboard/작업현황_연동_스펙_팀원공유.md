# 작업현황(Work Status) 박스 자동 카운트 — 연동 스펙 (★1일 기준 누적)

> 목적: 대시보드 우측 **작업현황 박스**(완료 / 사이클 / 평균)가 **한 사이클(파이프 적재 완료)마다 자동으로 쌓이게**.
> **집계 단위 = 1일(하루 총량). 자정 넘어 다음 날이 되면 0부터.** 시작/종료를 반복하거나 브리지가 재시작돼도 **그날 총량은 유지**(파일 저장).
> 현재 상태: 박스 `완료 0개 / 사이클 — / 평균 —` 고정 = 미배선(브리지가 `d.work` 안 보냄).
> 작업 파일 = **2개**(auto_runner_workflow.py + rpi_dashboard_ws_bridge.py). **대시보드(HTML) 수정 0**.

---

## 0. "한 사이클" 정의
한 사이클 = **파이프 1개 완주**:
```
검출 → 집기(PIPE_TO_CNC) → CNC 투입 → 가공 20초(그 사이 볼트/너트 분류) → 회수 → 적재(rack_count++)
```
- **완료(done) +1 = 적재 성공 시점.**
- **사이클 시간(cycle_s) = 집기 시작 ~ 적재 완료**(CNC 20초 포함).

## 0-1. 집계/초기화 규칙 (★중요)
- **누적 단위 = 캘린더 1일.** 그날 적재한 파이프 수를 계속 더함.
- **리셋 = 날짜가 바뀔 때만.** (시작 버튼·종료·브리지 재시작으로는 **리셋 안 함**)
- **저장 위치 = 파일**(`work_stats.json`) → 재시작·정전에도 그날 값 유지.
- **자정 롤오버:** 보고 시점 + 스냅샷 생성 시점에 `저장된 날짜 != 오늘`이면 0으로 리셋 후 진행(운전 중 자정 넘어가도 자동 0).

## 1. 데이터 계약 (대시보드는 이미 소비 — HTML 수정 0)
```
d.work = { done, cycle_s, avg_s, last: { cycle_s, at } }
```
- `done` = **오늘** 적재 완료 누적 수
- `cycle_s` = 직전 사이클 시간(초)
- `avg_s` = **오늘** 평균 사이클 시간(초)
- `last` = { cycle_s, at("HH:MM") }

대시보드: `applyIncoming`이 `d.work`→`state.work` 병합, 작업현황 패널이 `state.work` 렌더. **변경 없음.**

## 2. 파일 ①: `auto_runner_workflow.py` (사이클 시간만 측정·보고)
> auto_runner는 **"파이프 1개 끝났고 cycle_s초 걸렸다"** 만 알려줌. 누적·평균·날짜·저장은 **브리지가** 담당.

### 2-1. run() 지역변수 추가 (`aborted = False` 근처)
```python
    pipe_pick_start = 0.0     # 현재 파이프 집기 시작 시각
```
> (이전 스펙의 `cycle_times`는 불필요 — 평균은 브리지가 하루치로 계산)

### 2-2. 집기 시작 시각 기록 (`step("PIPE_TO_CNC")` 직후)
```python
                if target == "PIPE":
                    step("PIPE_TO_CNC")
                    pipe_pick_start = _now()          # ★사이클 시작(집기→적재)
                    r = _pipe_to_cnc(api, arm_mm, v, dry_run)
```

### 2-3. 적재 성공 시 보고 (`rack_count += 1` 블록)
```python
                if r2[0] == "done":
                    rack_count += 1
                    set_cnc_busy(False)
                    need_scan = False
                    cyc = max(0.0, _now() - pipe_pick_start)   # 이 파이프 사이클 시간
                    rw = getattr(api, "report_work", None)      # 구브리지/dry_run이면 None → no-op
                    if rw:
                        rw(cycle_s=round(cyc, 1))               # ★done 안 보냄. 브리지가 하루치 +1
                    if log:
                        log.log_sort(object_type="PIPE", bin=f"rack{rack_count}", success=True)
```

## 3. 파일 ②: `rpi_dashboard_ws_bridge.py` (하루치 누적 + 파일 저장 + 송출)

### 3-1. 경로 + 헬퍼 (기존 `LIFE_USAGE_PATH` 패턴과 동일)
```python
from datetime import datetime
WORK_STATS_PATH = Path(__file__).resolve().parent / "work_stats.json"

def _today():
    return datetime.now().strftime("%Y-%m-%d")

def _work_load():
    try:
        d = json.loads(WORK_STATS_PATH.read_text(encoding="utf-8"))
    except Exception:
        d = {}
    if d.get("date") != _today():               # 날짜 다르면(=새 날 or 첫 실행) 0부터
        d = {"date": _today(), "done": 0, "sum_s": 0.0, "last": None}
    d.setdefault("done", 0); d.setdefault("sum_s", 0.0); d.setdefault("last", None)
    return d

work_stats = _work_load()                        # 브리지 시작 시 그날 값 복원

def _work_save():
    try:
        WORK_STATS_PATH.write_text(json.dumps(work_stats, ensure_ascii=False), encoding="utf-8")
    except Exception:
        pass

def _work_rollover():                            # 자정 넘어가면 자동 0
    if work_stats.get("date") != _today():
        work_stats.update({"date": _today(), "done": 0, "sum_s": 0.0, "last": None})
        _work_save()
```

### 3-2. 보고 함수 + DI 등록
```python
def _report_work(cycle_s=None):
    _work_rollover()
    work_stats["done"] += 1
    if cycle_s is not None:
        work_stats["sum_s"] += float(cycle_s)
    work_stats["last"] = {"cycle_s": cycle_s, "at": datetime.now().strftime("%H:%M")}
    _work_save()
```
`_PickApi` 안:
```python
    report_work = staticmethod(_report_work)
```

### 3-3. build_snapshot 반환에 work 추가 (스냅샷 만들 때도 롤오버 체크)
```python
    _work_rollover()
    _done = work_stats["done"]
    _avg = round(work_stats["sum_s"] / _done, 1) if _done else None
    _last = work_stats.get("last")
    work = {"done": _done, "avg_s": _avg,
            "cycle_s": (_last or {}).get("cycle_s"), "last": _last}
```
return dict에 추가:
```python
            "work": work,
```

## 4. (보너스) CNC "적재 n/2"
CNC rack은 **세션 내 적재 수**(0~2, 적재함 비우면 리셋)라 **하루 누적 done과 다름**.
- 정확히 하려면 auto_runner가 `set_cnc_busy(False)` 때 현재 `rack_count`(세션값)도 별도 보고(`api.set_rack(n)`)하는 게 맞음 → work(하루)와 rack(세션)은 **다른 값**이니 분리.
- 작업현황(하루 done)만 먼저 하고, CNC rack은 별도로 가도 됨.

## ★별건 수정: CNC 패널 "회수 대기" 멈춤 (auto_runner 1줄)
> 작업현황과 별개지만 같은 파일·같은 구간이라 같이 정리.

**증상:** 회수(grab)를 했는데도 CNC 패널이 **"회수 대기"(DONE_WAIT)에서 안 바뀜.** 특히 적재(rack) 티칭이 없어 `place_to_rack`이 실패하면 **영구 멈춤.**

**원인:** `set_cnc_busy(False)`(= CNC EMPTY로 바꾸는 신호)가 **회수 직후가 아니라 적재 완료 후에만** 호출됨. 회수→적재 구간(auto_runner_workflow.py 타이머 만료 분기):
```python
                cnc_fail = 0
                r2 = _place_to_rack(api, rack_count, dry_run)
                if r2[0] == "aborted":
                    aborted = True; break
                if r2[0] == "done":
                    rack_count += 1
                    set_cnc_busy(False)          # ← 적재 성공해야만 여기 도달 → 실패하면 영영 안 풀림
```

**고치는 위치:** 회수 성공 직후(`cnc_fail = 0` 다음, place 호출 전)에 한 줄 추가:
```python
                cnc_fail = 0
                set_cnc_busy(False)             # ★회수 성공 = 파이프가 CNC서 빠짐 → CNC 즉시 비움(적재 결과와 무관)
                r2 = _place_to_rack(api, rack_count, dry_run)
```
- 기존 `rack_count += 1` 블록 안의 `set_cnc_busy(False)`는 **중복되지만 무해**(idempotent) → 그대로 둠.
- **효과:** 회수하는 순간 "CNC 비어 있음"으로 전환. 적재가 늦거나 실패해도 CNC 표시는 정확.
- **부수효과(의도):** detect "파이프 제외" 플래그도 풀려 → CNC가 비었으니 다음 스캔부터 파이프 재인식(맞는 동작). 적재 모션 중엔 robot_busy로 detect 정지라 영향 없음.
