# 삼보모터스 로봇팔 자동 분류 대시보드 — 기능 상세 정리

> 본체: `sambo_robot_arm_dashboard.html` (단일 파일, 약 214KB · 구조+CSS+JS 인라인)
> 백엔드: `rpi_dashboard_ws_bridge.py` (WebSocket `:8765`, CAN↔WS 브리지)
> 보조: `sambo_object_overlay.js`(비전 오버레이) · `sambo_vision_state.py`(비전 상태 리더) · `three.min.js`
> 서빙: 라파 `sambo-dashboard.service` = `http.server 8090`

문서 기준: choi 브랜치 `choi/dashboard/` 최신본. 함수명·상수는 코드에서 직접 추출.

## 0. 코드 한눈에 — 동작 골격

대시보드는 **상태객체 1개(`state`)** 를 중심으로 돈다. 모든 화면은 `state`를 읽어 다시 그리고, 들어온 데이터(WS 또는 DEMO)는 `state`를 갱신한다.

```
연결        →  데이터 갱신       →  렌더
connectWS()    applyIncoming()      renderAll() ─┬─ renderHeader()
demoTick()     applyCanFrame()                   ├─ renderPath()        (단계 차트)
(서버 없으면)   → state 갱신                       ├─ renderRightPanel()  (관절/모터/분류)
                                                  └─ renderPrimary()
frame()  ← requestAnimationFrame 루프가 draw3D() 매 프레임 호출
```

- 진입: 페이지 로드 끝에서 `setMode("AUTO_RUN")` → `connectWS()` → `requestAnimationFrame(frame)`
- 렌더 모음: `renderAll()` (1줄 호출로 헤더·경로·우측패널 등 일괄 갱신), `requestUiRender()`로 과도호출 방지
- 3D는 별도: `frame()` 루프가 `draw3D()`를 매 프레임 호출 (`drawThreeRobot()` 성공 시 Three.js, 실패 시 `drawNative3D()` 캔버스 폴백)

### 핵심 상태객체 `state` (라인 899~)
| 키 | 내용 |
|---|---|
| `mode` | `"AUTO_RUN"` / `"MANUAL"` |
| `demo` | DEMO 모드 여부(실데이터 오면 false로) |
| `ws` | WebSocket 핸들 |
| `robot.joints[]` | 6모터(M1~M6) 현재각·목표각·온도·부하·상태 |
| `gripper` | state(OPEN/CLOSE)·sg90_angle·tof_mm·pick_ready |
| `vision` | target·confidence·stable_frames·bbox·correction(dx/dy mm) |
| `path` | current_step·steps[9]·progress_percent |
| `sorting` | bolt·nut·total·cycle_s |
| `system` | server_connected·can_status·camera_status·ai_status·estop |
| `can_health` | received·errors·delay_ms·last_rx_ms |
| `digital_twin` | cmd/telemetry/current CAN id·latency·last_cmd/ack |

## 1. 한눈에 보기

사람 동작 티칭 → 카메라/AI 물체 인식 → 위치 보정 → 6축 서보로 볼트·너트를 자동 분류하는 로봇 셀을 **한 화면**에서 감시·조작하는 운영 대시보드.

- **실시간 텔레메트리**: WebSocket(10Hz)으로 관절각·온도·부하·CAN·ToF·비전을 받아 표시
- **DEMO 모드**: 서버 미연결 시 `demoTick()`이 시뮬레이션 값 생성, 실데이터 도착 시 자동 해제
- **2개 모드**: 자동 운전 / 수동 시험 · **3개 안전 버튼**: 시작 · 중지(HALT) · 정지(STOP)
- 스크롤 없는 단일 화면

## 2. 화면 레이아웃

```
┌─ 상단 제어바: 로고 | 시작·중지·정지 | 서버·CAN·카메라·AI 칩 | 시계 ─┐
├─ 툴바: [자동 운전][수동 시험] · HOME복귀 · 운전준비점검 · 카메라 · 시스템연결도 · 통신상세 ─┤
├─ 단계 차트 (01~09 + 현재 단계 + 진행률 %) ─────────────────────┤
│  메인 스테이지 (좌: 그리퍼 카메라 / 우: 3D 트윈)   │ 관절 상태 / 모터 상태 / 분류 현황 │
├─ 하단: ToF 거리 | 예약 영역 | 이벤트 로그 ──────┴────────────────┤
└─ 우하단 떠있는 AI 작업 도우미 버튼 ───────────────────────────┘
```

레이아웃 전환: `setMode()` → `renderStandardStage()`(자동) / `renderManualStage()`(수동)가 `#mainStage` 내용을 통째로 교체.

## 3. 상단 제어바 (Header) — `renderHeader()`

| 요소 | 동작 | 함수 |
|---|---|---|
| **▶ 시작 (AUTO RUN)** | `AUTO_START` 송신, 스캔 자세 이동 | `startAutoRun()` |
| **⏸ 중지 (HALT)** | `HALT` 송신, 진행 이동 선점 + 현재 실측각 토크 홀드 | `haltRobot()` |
| **■ 정지 (STOP)** | `AUTO_STOP` 송신, 스캔 복귀 후 원점 180° | `stopAutoRun()` |
| 서버 상태칩 | RPi WebSocket 연결 표시 | `setHeaderStatus()` |
| CAN 상태칩 | OK/WARN/STALE + 마우스오버 툴팁(`#canTip`) | `renderHeader()` |
| 카메라·AI 칩 | 카메라/YOLO 상태 | `renderHeader()` |
| DEMO 배너 | 시뮬레이션 동작 중 표시 | `state.demo` |
| 시계 | 현재 시각 | `currentTime()` |

- 버튼 활성/비활성(시작 vs 정지 상태)은 `updateRunHeaderControls()`가 토글.
- `startAutoRun()` 내부: `state.auto.running=true` → `sendDashboardCommand("AUTO_START")` → 로그 + 렌더.

## 6. 메인 스테이지

### 6-1. 그리퍼 카메라 / Gripper Cam
- MJPEG 스트림(기본 `http://<host>:8091/?action=stream`) 표시. 관련 함수: `applyGripperStream()`, `setGripperStream()`, `promptGripperUrl()`(주소 입력), `onGripperStreamError()`(오류 시 플레이스홀더 복귀)
- 미연결 시 "CAM" 플레이스홀더 → 클릭하면 스트림 주소 입력

### 6-2. 로봇 3D 분류 셀 / Sorting Twin (Three.js)
실제 STL 모델을 현재 관절각대로 움직이는 디지털 트윈.

**렌더 파이프라인**
- `initThreeRobot()` : 씬·카메라(`PerspectiveCamera 42°`)·조명·바닥/격자·재질 생성, STL 로드(`loadActualStlRobot`)
- `drawThreeRobot()` : 매 프레임 — 텔레메트리각을 `getStlSafeAngleMap()`(충돌 클램프) → `getVisualJointAngleMap()` → `applyStlAngles()`로 모델에 적용 후 카메라 배치·렌더
- `addThreeSortBins()` : 볼트통·너트통·스캔영역·라벨 생성

**관절각 → 3D 매핑** (`TWIN_AXIS_CONFIG`, 라인 926~)
- M1~M6 각각 sign/gain/home(영점) 정의. 어깨는 **거울쌍**(M2 sign +1 / M3 sign −1) → `shoulderMirrorAngle()`로 평균
- 변환 체인: `rawToLogicalAngleByIndex()` → `getTwinPoseFromAngles()` → `stlRotationsFromTwin()` → `applyStlAngles()`

**충돌 감시** — `stlCollisionReport()` / `getStlSafeAngleMap()`
- `r.staticKeepouts`: 베이스 하우징·볼트통·너트통 프레임을 침범 금지 박스로 설정 → 침범 시 `warnCollisionLimit()` 경고 + 자세 클램프

**시점 조작 (툴바)**
| 버튼/조작 | 함수 |
|---|---|
| ↶15° / 15°↷ | `rotateView(±15)` → `updateRotDeg()` |
| − / + (줌 10%) | `zoomStep(±1)` → `updateZoomPct()` |
| 기본 시점 | `reset3DView()` |
| 마우스 드래그(좌우 회전/상하 틸트) | `bind3DDrag()` |

> Three.js 로드 실패 시 `drawNative3D()`가 순수 캔버스로 로봇/통/영역을 대체 렌더(`drawArmSegment`, `drawJoint3D`, `drawGripper3D`, `drawZone3D` 등).

## 9. 수동 시험 컨트롤 (MANUAL) — `renderManualRows()`

관절마다 **슬라이더 + 숫자입력 + 미세조정 + 적용**.

- 입력 핸들러: `manualJoint(i,val)`(슬라이더/숫자 입력 미리보기), `manualJog(i,±1)`(±1°), `sendManualJoint(i)`(적용→`MANUAL_MOVE`)
- 한계: `manualJointMin/Max()` + `jointSoftLimitLogical()`로 소프트리밋 clamp
- **어깨(J2)는 슬라이더 하나로 M2·M3 동시** — `J3` 행은 숨기고(`renderManualRows` 내 `if(j.id==="J3")return ""`), 한 번의 `MANUAL_MOVE`에 두 모터 타깃을 묶어 전송(따로 보내면 선점됨)
- **그리퍼(GR)**: `manualGripper()` / `manualGripperJog(±5)` / `sendManualGripper()`(→`GRIPPER`)
- 미리보기 자동복귀: `scheduleManualPreviewReset()` 등(조작 안 하면 현재각으로 환원)
- 공통 버튼: `goHome()` · `toggleGripper()` · `manualAction('연결 확인')` · `manualAction('서보 Torque ON/OFF')`
- 숫자칸 휠/키 조정: `manualWheel()` · `manualAngleKey()`

## 13. 통신 / 데이터 계약

### WebSocket — `getWsUrl()` · `connectWS()` · `applyIncoming()`
- 주소: `ws://<host>:8765` (기본 localhost), 라벨 `#wsUrlLabel`
- 수신: `applyIncoming(msg)`가 `state`(joints/system/vision/gripper/can_health) 갱신 → 첫 실데이터에서 `state.demo=false`
- CAN 프레임 직접 표시용: `applyCanFrame()`

### 대시보드가 보내는 명령 — `sendDashboardCommand(command, payload)`
| 명령 | 트리거 함수 | 동작(브리지) |
|---|---|---|
| `AUTO_START` | `startAutoRun()` | 스캔 자세 이동 |
| `AUTO_STOP` | `stopAutoRun()` | 스캔 복귀 후 원점 180° |
| `HALT` | `haltRobot()` | 즉시정지 + 현재각 토크 홀드 |
| `HOME` | `goHome()` | 원점 복귀(모터별 각 payload 포함) |
| `MANUAL_MOVE` | `sendManualJoint()` | 다중 모터 동시 S-curve(거울쌍 묶음) |
| `GRIPPER` | `sendManualGripper()`·`toggleGripper()` | MG90S 각 설정 |
| `PING` | — | 수신 경로 확인(무동작) |

> 브리지(`rpi_dashboard_ws_bridge.py`)는 40Hz S-curve로 setpoint를 CAN `0x100`에 스트리밍하고, 새 명령이 오면 generation 기반으로 진행 이동을 선점. 단일관절용 `SET_JOINT_ANGLE`도 지원.

### DEMO 시뮬레이션 — `demoTick()`
- 서버 없을 때 관절·센서·단계를 가짜로 진행시켜 화면을 살아있게 유지. `applyAutoDemoPose()`로 자동 자세 변화.

## 14. 안전

- **HALT** `haltRobot()`: 트래젝토리 선점 + 현재 실측각 홀드 → 그 자리 정지
- **STOP** `stopAutoRun()`: 스캔 복귀 후 원점 안전 종료
- **충돌 keepout**: `stlCollisionReport()`/`getStlSafeAngleMap()`로 침범 자세 클램프 + `warnCollisionLimit()` 경고
- **소프트 리밋**: `jointSoftLimitLogical()`로 수동 명령각 끝단 clamp(하드스톱 충돌 방지)
- E-STOP(서보 전원 차단)은 하드웨어 별도. 화면엔 `triggerEstop()`/`resetEstop()` 상태 표시용 훅 존재
