# 삼보모터스 5축(6모터) 로봇팔 — 작업 정리 (통합본)

최종 갱신: 2026-06-03
구성: **RPi5(CANable) ─ CAN ─ STM32(NUCLEO-F103RB) ─ UART ─ STS3215 ×6**, + Nano(MCP2515) 가상센서

---

## 1. 시스템 개요

```
RPi5 (CANable, gs_usb) ──┐
                         ├── CAN 125kbps / sample-point 62.5% ──┐
Arduino Nano (MCP2515) ──┘                                       │
STM32 NUCLEO-F103RB ─────────────────────────────────────────────┘
   └ UART(PA9/PA10,1Mbps) ─ Bus Servo Adapter ─ STS3215 ×6 (ID 1~6)
```
- RPi: 명령 송신 + 텔레메트리/전류/센서 수신 (두뇌)
- STM32: CAN↔서보 브릿지. 명령 받아 제어, 상태 회신
- Nano: 가상 센서값 0x300 송신 (별도 노드)

**CAN 셋업 (규약 §5.1):**
```bash
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 125000 sample-point 0.625
sudo ip link set can0 up
```
- 2번째 줄 반드시 한 줄. gs_usb는 restart-ms 미지원 → Bus-off 시 수동 down/up.
- STM 타이밍: PCLK1=32MHz, Prescaler=16, BS1=9TQ, BS2=6TQ, PB8=RX/PB9=TX(AFIO 리맵).

## 2. CAN 프로토콜 (현재 STM 펌웨어 기준)

| ID | 방향 | 용도 |
|---|---|---|
| `0x100` | RPi→STM | 모터 명령 |
| `0x200` | STM→RPi | ACK [cmd, id, status] |
| `0x201` | STM→RPi | 텔레메트리 [id, ax10_lo, ax10_hi, tempC, load_lo, load_hi, flags] |
| `0x202` | STM→RPi | 전류 [id, cur_lo, cur_hi, ok] (≈6.5mA/LSB) |
| `0x300` | Nano→RPi | 가상 센서 |

**0x100 명령:**
| cmd | 의미 | 프레임 |
|---|---|---|
| 0x01 | 위치(step) | [01,id,step_lo,step_hi,mv_lo,mv_hi,0,0] |
| 0x03 | 각도(angle×10) | [03,id,ax10_lo,ax10_hi,mv_lo,mv_hi,0,0] (180°=1800) |
| 0x04 | 영점 180°(중위보정) | [04,id,...] 안 움직임, EEPROM 영구 |
| 0x05 | 영점 임의각(오프셋 직접 기록) | [05,id,ax10_lo,ax10_hi,...] 안 움직임, EEPROM 영구 |
| 0x02 | 토크 ON/OFF | [02,id,0,0,0,0,torque,0] |
| 0x7F | ping | |

- 0x201 각도는 **angle×10** (RPi에서 ÷10). load = 부하 추정(실제 압력 아님).

## 3. STM32 펌웨어

**위치:** `c:\Users\KDS29\sts3215\src\main.cpp` (PlatformIO, nucleo_f103rb)
**빌드/업로드:**
```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run -d "c:\Users\KDS29\sts3215"           # 빌드
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run -d "c:\Users\KDS29\sts3215" -t upload  # 업로드
```

**기능:**
- `SERVO_COUNT 6`. 명령: step/angle/torque/ping + 영점 2종.
- **영점 180°** (`setMiddleCalibration`): Torque_Enable(0x28)=128 → 현재=2048(180°), EEPROM.
- **영점 임의각** (`setReferenceAngle`): 오프셋 레지스터(0x1F/0x20) 직접 기록.
  - `새 오프셋 = 목표step − 현재present + 현재오프셋`, ±2047 클램프, 락(0x37) 언락→기록→락.
  - ⚠ 오프셋 부호비트(bit11) 인코딩이 모델/펌웨어와 맞아야 함 → **한 서보로 먼저 테스트**.
- 텔레메트리: 모터 1개씩 순환, 0x201(각도/온도/부하) + 0x202(전류) 송신. `TELEMETRY_PERIOD_MS`(150) 낮추면 전류 빠름.
- 사용 레지스터: Torque 0x28, GoalPos 0x2A, PresentPos 0x38, Load 0x3C, Temp 0x3F, Current 0x45, Offset 0x1F, Lock 0x37.

## 5. 영점(캘리브레이션) 컨벤션 — ★중요

세 가지 약속이 공존하므로 **운전 방식에 따라 통일** 필요:

| 컨벤션 | 2048(중심)=무엇 | 어디서 씀 |
|---|---|---|
| **수동(키보드 v2)** | M2=360/M3=0/M4=360, 그외 180 | 한방향 풀가동 텔레옵 |
| **IK(arm_ik.py)** | 각 모터별 cal_ref로 변환 | 자율 좌표 제어 |
| 레포 servo_driver | 관절 home각=2048 | 레포 코드 |

**핵심 사실:**
- EEPROM 오프셋이든 소프트웨어든 **라벨만 바꾸지 물리 가동범위(360°)는 그대로**.
- 현재를 360이라 하면 거기서 **아래로만** 360° 가능 → 풀가동 쓰려면 **영점 전에 관절을 끝쪽에 둘 것**.
- 오프셋 범위 ≈ ±180° → 0/360은 한계 끝(±1스텝).
- arm_ik.py는 모터별 영점기준(`MOTOR_CAL`)을 받아 **각 모터 식을 따로** 적용하므로 360/0과 공존 가능.

## 6. M2·M3 거울쌍 — 부하 분담 / 과열

**증상:** 어깨(최대 하중) 두 모터 중 **M3만 과열, M2는 시원**.
**원인:** 위치제어 서보는 위치오차에만 비례해 토크를 냄. 두 모터 영점이 같은 물리각에 안 맞으면, 중력 평형점에서 한쪽(M3)만 오차가 남아 떠받치고 다른쪽(M2)은 힘을 풂. → **한쪽만 뜨겁다 = 분담 실패 신호.**
**해결(코드=부분적):**
1. 무게 실은 자세에서 둘 동시 재영점 → 평형점 일치.
2. **프리로드**(`MIRROR_PRELOAD`, `[` `]`): M2 +preload, M3 −preload로 **둘 다 중력 반대로 밀게**. 정지 중에도 0.3s마다 재송신. 전류 모니터로 **M2≈M3** 되게 튜닝. 과대 시 둘 다 발열(co-contraction).
3. 한계: 분담이지 증폭 아님. 무게가 한 모터 스톨토크 근처면 기계적 보완(카운터밸런스) 필요.
**미러 동작:** M2 sign −1, M3 sign +1 → w 누르면 M2↓/M3↑ (합 일정). 물리적으로 같은 쪽으로 도는지 실측 확인(아니면 부호 뒤집기).

## 8. 역기구학 arm_ik.py (신규)

**설계(검토의 검토):** 코어 = **기하학적 2링크 해석해**(레포 ik.py 계열) + 물리치수/작업구조(사용자 DLS) + 우리 영점 변환층.
- **왜 DLS 안 씀:** 5축은 6자유도(위치3+자세3) 완전제약 불가 → DLS는 과결정·수렴실패. 기하학은 **위치+접근방향만** 잡고 손목회전(J5) 자유 → 항상 닫힌해, 0mm 정확, 빠름.
**흐름:** ①J1으로 목표 방향 회전 → ②남은 건 평면 2링크(어깨·팔꿈치) **삼각형(코사인 법칙)**으로 한 방에 → ③J4로 그리퍼 기울임(L3 보정) → ④`joints_to_motor_angles`로 **모터별 영점기준 적용**.
**물리치수:** H=69.3, D1=48.5, L1=245, L2=213, L3=87 (mm).
**검증:** FK 라운드트립 4개 타깃 **오차 0.000mm**. 거울쌍 M2+M3=360 확인.
**모터 변환식:** `명령각 = cal_ref + DIR×(관절각 − JOINT_DEG_AT_CAL)`. M2(360,−1)/M3(0,+1)/M4(360)/그외(180).
**⚠ 실측 필요(`[MEASURE]`):**
- `DIR` (±1): 관절↑일 때 서보 읽음 ↑/↓
- `JOINT_DEG_AT_CAL`: 영점 누른 그 자세의 IK 관절각(deg)
→ 팔 조립·영점 후 1회 캘리브레이션으로 확정.
**출력 연결:** `joints_to_motor_angles(q)` → {모터:각도} → STM `CMD_SET_ANGLE`(0x03).
**미완:** horizontal 접근(누운 볼트) 구현돼 있으나 self-test는 down만. 작업영역 체크 함수 포함.
